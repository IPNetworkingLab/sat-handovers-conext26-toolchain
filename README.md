# Main toolchain of the paper "Paving the Way for Link-State Routing in Satellite Networks with Fast and Seamless Ground Station Handovers"

This repository contains the toolchain leveraged in the paper ["Paving the Way for Link-State Routing in Satellite Networks with Fast and Seamless Ground Station Handovers"]() to be presented at [CoNEXT'26](https://conferences.sigcomm.org/co-next/2026/#!/home).

Crate dependencies are encoded as git submodules pointing towards the exact version of the code used for the paper.

## How to use this repository?

First, clone it from GitHub:

```console
$ git clone https://github.com/IPNetworkingLab/sat-handovers-conext26-toolchain.git
```

Then, initialise the submodules and build the full toolchain:

```console
$ git submodule update --init --recursive
$ cargo build --release
```

The toolchain expects a specific project structure.
In the following example, we consider that we evaluate two different topologies, `myfirsttopo` and `mysecondtopo`, in a single experiment `myfirstexperiment`.

```console
$ROOT
|
| - topos
| | - <myfirsttopo>.yaml
| | - <mysecondtopo>.yaml
|
| - kepler
| | - <myfirsttopo>.json
| | - <mysecondtopo>.json
|
| - <myfirstexperiment>
| |
| | - <myfirsttopo>
| | | - toolchain_params.toml
| | | - topology
| | | - simulation
| |
| | - <mysecondtopo>
| | | - toolchain_params.toml
| | | - topology
| | | - simulation
```

The `topos` directory contains the constellation code for each topology, as defined by [draft-piraux-space-constellation-code](https://datatracker.ietf.org/doc/html/draft-piraux-space-constellation-code) version 01 augmented with a ground station section.

The `kepler` directory contains, for each topology, the output of the crate [`handover-filter`](https://github.com/IPNetworkingLab/handover-filter.git) based on the constellation code provided in the `topos` directory.

> Note: The content of the `kepler` directory can be automatically generated by the toolchain.

Each experiment directory follows the same structure, it contains dedicated sub-directories for each topology.
Within each topology sub-directory, a `toolchain_params.toml` file **must** be provided, it contains the configuration of the toolchain for that specific topology in the scope of that specific experiment. 
The sub-directory also contains two additional sub-directories, `topology` which contains a [DUNE configuration file](https://github.com/nrybowski/DUNE.git) representing the state of the topology per evaluated handover, and `simulation` which contains the output of the [`convergence-simulator`](https://github.com/IPNetworkingLab/convergence-simulator.git) crate for each evaluated handover.
The files in the `topology` directories are generated with the [`constellation-builder`](https://github.com/IPNetworkingLab/constellation-builder.git) crate.

Here is a sample `toolchain_params.toml` configuration file:

```toml
constellation_code = "./topos/leo.yaml"

[handover_filter]
file = "./kepler/leo.json"
max_sat_per_gw = 9
max_gw_per_sat = 4
new_format = true
max_delay = 0

[[simulations]]
method = "Nested"
fib_check = true

[[simulations]]
method = "Sequential"
fib_check = true
```

The `constellation_code` entry provides the path towards the code of the constellation.

The `handover_filter` section configures the related crate by specifying (_i_) the path towards the possible connectivity events (`file`), (_ii_) the maximum number of feeder links per ground station (`max_sat_per_gw`), and (_iii_) the maximum number of radio per satellite (`max_gw_per_sat`).
The `new_format` entry must be set to `true`, it differentiates the current output format of the `handover-filter` crate with a legacy format.
The `max_delay` entry is not used in the paper and may be left to 0.

Each `simulations` entry configures a single convergence simulation.
The synchronisation mechanisms, as defined in the paper, are configured with the `method` entry.
Currently, only `Nested` and `Sequential` are supported.
Simulator sanity checks applied at runtime are enabled with the `fib_check` entry.

The toolchain can populate the `kepler`, `topology` and `simulations` directories by running:

```console
$ cargo run --release -- -c $ROOT/<myfirstexperiment>/<myfirsttopo> --no-cache -s
```

where `-c` specifies the path towards a given `toolchain_params.toml` configuration file, `--no-cache` specifies to compute the candidate connectivity events (`kepler`) from scratch, and `-s` specifies that all intermediate files must be dumped in the directory structure specified above.

> WARNING: The toolchain will use as many cores as possible to run simulations in parallel in order to save time.
> The more core available, the faster the experiment will terminate.

Once the `kepler` directory has been populated, the `--no-cache` cli argument may be dropped in subsequent calls to the toolchain.

> Note: If the `handover_filter` section of the toolchain configuration file is modified, the `--no-cache` argument **must** be provided to regenerate a sequence of connectivity events taking into account the changes.
